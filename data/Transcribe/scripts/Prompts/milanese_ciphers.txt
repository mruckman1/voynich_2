You are extracting cipher key tables from Visconti-Sforza
diplomatic cipher documents held at the Archivio di Stato
di Milano (ASMi), dating from approximately 1380–1450.

These are northern Italian diplomatic cipher keys produced
for the Visconti and Sforza courts. Each document typically
consists of one or more tables showing:
  — cipher symbols with their plaintext letter/syllable values
  — sometimes nomenclator entries (code words for proper nouns
    and frequently-used phrases)
  — sometimes null signs (meaningless symbols to confuse
    frequency analysis)

The primary purpose of extracting these documents is Phase D
of the Voynich decipherment project: comparing the statistical
fingerprint and structural properties of these known ciphers
to the Voynich manuscript's statistical profile. The sign
construction logic (how symbols are built from strokes) and
the encoding unit (letter vs syllable) are the key variables.

─────────────────────────────────────────────────────────────
WHAT TO SKIP — output nothing for any of the following:
─────────────────────────────────────────────────────────────
- Archival metadata stamps, catalog labels, or shelfmarks
  added by later archivists (note the document shelfmark in
  the document_id field, but do not create entries for it)
- Diplomatic text written in the cipher (the encrypted letter
  body) — we want the key, not the ciphertext
- Diplomatic text in plain Latin or Italian that forms the
  letter body — skip prose text, extract only key tables
- Dates and salutations of letters (note them in
  document_date and parties fields only)

─────────────────────────────────────────────────────────────
OUTPUT FORMAT — one JSON object per document:
─────────────────────────────────────────────────────────────

1. document_id
   The ASMi shelfmark or catalog reference as it appears
   on the document or accompanying archival slip.
   E.g. "Carteggio Visconteo, cart. 14, doc. 47"

2. document_date
   Date of the document if visible, transcribed exactly
   in whatever form it appears (Latin, Italian, or numeric).
   Null if not visible.

3. parties
   If visible: sender and recipient of the cipher, as named
   in the document. E.g. {"sender": "Galeazzo II Visconti",
   "recipient": "ambassador in Florence"}. Null if not stated.

4. encoding_unit
   Based on examining the key table, what does each symbol
   encode?
   "single_letter"    — each symbol = one plaintext letter
   "syllable"         — each symbol = a CV or CVC syllable
   "letter_and_null"  — mix of letters and null signs
   "nomenclator"      — mix of letters and code words
   "mixed"            — combination
   "unclear"          — cannot determine

5. alphabet_entries
   Array of entries from the cipher alphabet table.
   Each entry maps one cipher symbol to its plaintext value.

   For each entry:

   a. symbol_description
      Describe the cipher symbol visually using these terms:
      For geometric symbols:
        circle, oval, triangle, cross, star, crescent,
        vertical_stroke, horizontal_stroke, diagonal_left,
        diagonal_right, open_curve, closed_loop, hook,
        modified_letter (a Latin letter with a stroke or mark)
      For modified-letter ciphers (common in this period):
        Give the base letter then describe the modification:
        e.g. "a_reversed", "b_with_crossbar", "p_mirrored",
        "q_with_tick_above", "i_with_dot_below"
      If the symbol is clearly just a rotated or mirrored
      standard Latin letter, note that explicitly.

   b. plaintext_value
      The letter, syllable, or word that this symbol encodes,
      as written in the key. Transcribe exactly.

   c. is_null_sign
      true if the document labels this symbol as meaningless
      (a null / zeichen ohne Bedeutung). False otherwise.

   d. confidence
      "high" / "medium" / "low"

6. nomenclator_entries
   If the document includes a nomenclator section (code words
   for proper nouns or phrases), extract those separately:
   [{code_symbol_or_number, plaintext_phrase, confidence}]
   [] if no nomenclator section.

7. construction_logic
   After examining the full key: describe in one or two
   sentences what structural principle, if any, organizes
   the symbol set. E.g.: "Symbols are Latin letters with
   tick marks added in different positions" or "Symbols are
   arbitrary geometric shapes with no apparent family
   structure" or "Symbols form mirror pairs: b↔d, p↔q".
   This is an observation, not an interpretation.

8. notes
   Any other observation relevant to comparing this cipher
   to the Voynich manuscript. E.g.: language of plaintext,
   evidence of syllabic vs alphabetic encoding, estimated
   date range if not explicit. Null if nothing to add.

─────────────────────────────────────────────────────────────
RULES:
─────────────────────────────────────────────────────────────
- Do not attempt to decrypt the ciphertext body of letters
- If the key table is partially damaged or illegible, record
  what is visible and mark those entries confidence "low"
- construction_logic is an observation about symbol structure,
  not a claim about the cipher's relationship to the Voynich
- If multiple cipher keys appear in the same document
  (sometimes a key was revised), create one object per key

Output ONLY a JSON array (one object per document).
No explanation, no preamble, no markdown fences,
no trailing commentary.
